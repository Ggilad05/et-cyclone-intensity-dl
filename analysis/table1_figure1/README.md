# Table 1 and Figure 1 — provenance and rebuilding

This directory separates two **different analysis populations**. Do not treat the scripts as interchangeable.

## Table 1: actual modeled Control cohort

- `rebuild_control_cohort.py` reads the 45,378 unique storm IDs retained in the full-year, 24-h Control cohort (`reference/control_34_storm_keys.csv`). This is a compact derivative of `control_34.csv`, containing only `storm_key` values, **not** model predictions or meteorological fields.
- It reads the original 3-hour cyclone-track NetCDF files to recover the **whole 6-hourly track**, selecting nonzero **odd `t` values** (`t % 2 == 1`), matching the extraction logic. It does not simply slice array positions `[::2]`.
- No additional genesis, motion, lifetime or 70-degree filter is applied: membership is defined exclusively by the Control storm-ID list.
- Region membership is read from `classifications/original/` (NH regions) and `classifications/revised/` (South Atlantic and exclusive Southern Ocean). SA IDs are removed from the SO group, but the broader geographic polygons may still overlap on the map.
- Actual checked results (2026-10-30): NH 21,629 storms / 387,404 six-hour steps; SH 23,749 storms / 433,610 six-hour steps; **total 45,378 storms / 821,014 six-hour steps**. These count the entire 6-hour storm trajectories, not individual lead-time forecast examples.
- The 24-h Control cohort is the basis for these figures. We have **not** established that it is exactly the union of storm IDs used by all four forecast horizons.

## Paper's Figure 1: broader storm-track climatology

- The manuscript figure supplied by the researcher is preserved as `reference/figure1_original_supplied.pdf`.
- `legacy/figure1_original_recovered.py` is a **recovered source** from the code pasted in conversation, not a checked copy of the original `.py` on disk. It uses the original `pre_tracks` screening (genesis 20–60 degrees, >16 nonzero 3-hour tracking steps, propagation rules) and does **not** apply the model's maximum absolute latitude filter of 70 degrees or restrict membership to Control IDs.
- The broader climatology can therefore include high-latitude cyclone trajectories not used in model training or evaluation. This is intentional and must also be disclosed in the manuscript figure caption or methods, not just here.
- **Known historical inconsistency requiring verification**: the pasted legacy script skips `year <= 1979` and divides by `2020-1979 = 41` years, so if that was indeed the exact script used, it covers **1980–2020**, notwithstanding the `1979–2020` filename/caption. Verify before claiming the plot represents 1979–2020. Do not silently rewrite the archival source.
- The paper figure may also have been generated by an earlier/different revision: confirm the source script before making a strict provenance claim.

The Control-based script *also* creates a 5-degree density map, but this is a **cohort-limited alternative** and is **not** the manuscript's chosen high-latitude climatology.

## Run Table 1 on HPC (from repository root)

```bash
python analysis/table1_figure1/rebuild_control_cohort.py \
  --control-csv analysis/table1_figure1/reference/control_34_storm_keys.csv \
  --classifications-dir classifications \
  --data-dir /arctic2/shreibshtein/MasterProject/OrCyclones/ERA_5_Track \
  --out-dir outputs/table1_figure1/control_cohort \
  --no-plot
```

Remove `--no-plot` to produce the *Control-only* map. Output files go into the Git-ignored `outputs/` directory.

**Environment**: Python 3, NumPy, xarray plus a NetCDF backend; Cartopy, Matplotlib, Shapely for map rendering.

## Data availability and source mapping

- Raw ERA5 tensor files and tracking NetCDFs are **not** committed.
- The Control storm-ID manifest is small (~1 MB), useful for reproducing the precise cohort, and contains no predictions.
- The storm ID lists are already versioned under `classifications/` in the starter repository; this patch does not replace them.
- The original ERA5 extraction code should be imported as an unmodified historical snapshot in a later commit, once the original file is located and vetted (rather than copying an incomplete pasted version from chat).
